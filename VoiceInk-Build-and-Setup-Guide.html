VoiceInk: Build and Setup Guide

Version 1.1 · Last updated: Tue, 29 Sep 2026 15:55 · Author: Mahesh Mirchandani
From a real build performed on Mon, 15 Sep 2026 on a MacBook Pro 16″ (M1 Max). Every command below was actually run; every error listed actually happened.
New in version 1.1: a warning about the in-app updater and a safer update script (section 10.1), a clean-install step (section 4.3), and a fix for lost Accessibility permission (section 9).

macOS only

VoiceInk is a native macOS application (Swift and CoreML). There is no Windows or Linux version, and none can be built from this source code. You need a Mac.

1. What VoiceInk is, and why build it yourself

VoiceInk is a dictation app for macOS. You hold a key, speak, release, and your words appear as text at the cursor in whatever app you are using. Transcription runs entirely on your Mac using local AI models, so nothing you say leaves the machine. An optional second stage passes the transcript through a local language model (via Ollama) to strip filler words and fix punctuation, still fully offline.

The app is open source under the GPLv3 licence (github.com/Beingpax/VoiceInk). The developer sells a compiled version with a licence; building from source is free and entirely legal. What you give up by building it yourself:

  • Automatic updates. Local builds still contain the developer's updater (Sparkle), but accepting an update it offers replaces your build with the official one and breaks dictation (see the warning in section 10). You turn the update check off and update by rebuilding instead; a one-command script that does both is provided in section 10.
  • iCloud dictionary sync. Your personal dictionary stays on one Mac.
  • Support. No priority support or Discord access, and you are not funding further development. If you end up using VoiceInk daily, consider buying a licence anyway.

Everything else works: local transcription, AI enhancement, per-app modes, personal dictionary, launch at login.

3. Building from source

3.1 Preflight checks

Install Xcode from the App Store first if you have not (search for "Xcode", install, open it once and accept the licence). Then confirm everything in Terminal:

sw_vers                 # ProductVersion must be 14.4 or later
xcode-select -p         # must print /Applications/Xcode.app/Contents/Developer
xcodebuild -version     # prints the Xcode version; errors here mean the licence is not accepted
brew --version
git --version
cmake --version         # if missing: brew install cmake

If xcode-select -p prints a path ending in CommandLineTools, point it at the full Xcode:

sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

3.2 Install the Metal Toolchain

Since Xcode 26, the Metal GPU shader compiler is a separate download, and VoiceInk's AI dependencies need it. Fresh Xcode installations do not have it, and without it the build fails late with cannot execute tool 'metal' due to missing Metal Toolchain. Install it up front (about 700 MB):

xcodebuild -downloadComponent MetalToolchain
xcrun metal --version    # must now print a version instead of an error

3.3 Get the source

mkdir -p ~/Developer/voiceink-build
cd ~/Developer/voiceink-build
git clone https://github.com/Beingpax/VoiceInk.git
cd VoiceInk
Note

The build also creates ~/VoiceInk-Dependencies (the speech engine, whisper.cpp, lives there; the Xcode project references that exact path) and copies the finished app to ~/Downloads. Both are the project's own choices, not this guide's.

3.4 Build the app

One command does everything: it verifies your tools, clones and compiles whisper.cpp into an XCFramework (around 10 minutes, thousands of compiler lines, entirely normal), resolves about 28 Swift package dependencies, compiles VoiceInk in Release configuration, and copies VoiceInk.app to ~/Downloads:

make local LOCAL_CODESIGN_IDENTITY=-

Expect 15 to 25 minutes in total on the first run. Success looks like this at the end:

** BUILD SUCCEEDED **
Build complete! App saved to: ~/Downloads/VoiceInk.app
Check the real result

If the output instead contains ** BUILD FAILED **, find the first line containing error: further up and match it against section 9. Do not judge by the last line alone.

4. Signing and installing

4.1 Why signing matters here

macOS ties the Accessibility permission (which VoiceInk needs to type text into other apps) to the app's code signature. The build above is "ad-hoc" signed: a signature derived from the binary itself, which therefore changes on every rebuild. With ad-hoc signing, every rebuild looks like a brand-new app to macOS and you must re-grant Accessibility each time. That is livable if you rarely update. The better option is a one-off self-signed certificate, which keeps the signature identity stable so permissions survive rebuilds.

4.2 Create a signing certificate (recommended, one-off)

The following creates a certificate named VoiceInk Local, valid ten years, imports it into your login keychain and trusts it for code signing only. macOS will show one password dialog for the trust change; enter your Mac password and click Update Settings.

WORK="$(mktemp -d)" && cd "$WORK"

cat > codesign.cnf << 'EOF'
[req]
distinguished_name = dn
x509_extensions = codesign_ext
prompt = no
[dn]
CN = VoiceInk Local
[codesign_ext]
keyUsage = critical,digitalSignature
extendedKeyUsage = critical,codeSigning
basicConstraints = critical,CA:FALSE
EOF

openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem \
  -days 3650 -nodes -config codesign.cnf -extensions codesign_ext

openssl pkcs12 -export -out cert.p12 -inkey key.pem -in cert.pem \
  -passout pass:vlocal-import \
  -certpbe PBE-SHA1-3DES -keypbe PBE-SHA1-3DES -macalg sha1

security import cert.p12 -k ~/Library/Keychains/login.keychain-db \
  -P vlocal-import -T /usr/bin/codesign -T /usr/bin/security

security add-trusted-cert -p codeSign \
  -k ~/Library/Keychains/login.keychain-db cert.pem

security find-identity -v -p codesigning   # should list "VoiceInk Local"
cd ~ && rm -rf "$WORK"
Why the odd openssl flags

Homebrew's OpenSSL 3 writes modern PKCS#12 files that macOS cannot import (it fails with "MAC verification failed", a misleading message). The -certpbe/-keypbe/-macalg flags force the older format macOS accepts.

4.3 Re-sign and install

Xcode 26 refuses to sign with non-Apple certificates during the build (it silently falls back to ad-hoc, even when told otherwise), so the certificate is applied after the build:

codesign -f --deep --preserve-metadata=entitlements \
  -s "VoiceInk Local" ~/Downloads/VoiceInk.app
codesign --verify --deep --strict ~/Downloads/VoiceInk.app   # silence means success

rm -rf /Applications/VoiceInk.app
ditto ~/Downloads/VoiceInk.app /Applications/VoiceInk.app

# Keep only the copy in /Applications, and turn off the in-app update check
rm -rf ~/Downloads/VoiceInk.app ~/Developer/voiceink-build/VoiceInk/.local-build
defaults write com.prakashjoshipax.VoiceInk VoiceInkChecksForUpdatesOnLaunch -bool false

open /Applications/VoiceInk.app

If you skipped the certificate, leave out the two codesign lines. The app should launch and show its onboarding window.

Why delete the other copies

The build leaves two more copies of the app, one in ~/Downloads and one inside the build folder, and macOS knows about all of them. If one of those is launched, or is the copy that turns on Launch at login, permissions and updates attach to the wrong app. A single copy in /Applications avoids that. The update check is explained in section 10.1.

5. First-run setup

5.1 Permissions

VoiceInk's onboarding asks for the permissions it needs. If you miss one, or macOS revokes one after a rebuild, the manual paths are:

PermissionNeeded forWhere
MicrophoneRecording your voice (required)System Settings → Privacy & Security → Microphone → enable VoiceInk
AccessibilityTyping the text into other apps (required)System Settings → Privacy & Security → Accessibility → enable VoiceInk (use + and pick it from /Applications if it is not listed)
Screen & System Audio RecordingOptional: screen-context awareness and website-based mode switchingSystem Settings → Privacy & Security → Screen & System Audio Recording
[Screenshot: System Settings → Privacy & Security → Accessibility with VoiceInk enabled]
Onboarding's API key screen

One onboarding screen says "Verify API Key" and lists only cloud AI providers. You do not need any API key. Click Set It Up Later; the local Ollama option appears in the app's full settings afterwards (section 6).

5.2 Microphone selection

VoiceInk picks its input device independently of the system default. In the app, open Audio in the sidebar and select your microphone (an external USB microphone beats the built-in one). Confirm macOS sees it first with:

system_profiler SPAudioDataType   # your mic should appear with input channels

5.3 Download the transcription model

Open AI Models in the sidebar and download Parakeet TDT v3 (about 470 MB). For English dictation it beats the larger Whisper models on all three counts that matter: accuracy (lower word error rate on public English benchmarks), speed (it runs on the Neural Engine via CoreML and returns text near-instantly), and honesty (it does not hallucinate text during silences, a known Whisper habit). Optionally also download Whisper large-v3-turbo (about 1.6 GB) if you want a multilingual fallback.

[Screenshot: AI Models tab with Parakeet TDT v3 downloaded]
First run

The very first transcription takes a few extra seconds while macOS compiles the model. Every run after that is fast.

5.4 The dictation hotkey

The default hotkey is Left Control, used as hold-to-talk: hold it, speak, release, and the text appears. A quick tap instead starts hands-free recording (tap again to stop). To change the key: Modes → open your mode → Shortcut → Record, then press the key you want. Click the recorder field first so it is actively listening, otherwise the key press does not register. A right-hand modifier such as Right Option is a good alternative because nothing else on macOS uses it.

Set Language to English in the mode's Transcription section (rather than Auto-detect) if you dictate only in English.

5.5 Launch at login

In VoiceInk's Settings, enable Launch at login, so dictation is always one key-hold away. macOS remembers which copy of the app turned this on, which is another reason to keep only the copy in /Applications (section 4.3).

5.6 Test it

Open TextEdit, click into the document, hold the hotkey and say a sentence. The exact words should appear at the cursor. Repeat once in a browser text field. If nothing appears, the Accessibility permission is the usual culprit (section 9).

6. AI cleanup with Ollama

This optional stage passes each raw transcript through a local language model that deletes filler words ("um", "you know") and fixes punctuation before the text is typed out. Everything stays on your Mac.

6.1 Install Ollama and a model

brew install --cask ollama     # or download from ollama.com
ollama pull gemma4             # Google's open Gemma model, 8B, ~10 GB on disk

An 8B-class model is the sweet spot: tested head-to-head, the 8B Gemma followed the cleanup rules perfectly while a small 3B model (llama3.2) kept leaving filler words in. If disk or RAM is tight, try a mid-size Gemma variant and check its output against the test in 6.3.

6.2 Connect VoiceInk to Ollama

  1. Open Modes in the sidebar and click your mode (the default is called Dictation).
  2. In the AI Enhancement section: switch the toggle on, set AI Provider to Ollama, endpoint http://localhost:11434 if asked, and pick your model under AI Model (use Refresh models if the list is empty).
  3. On the Prompt row, click + to create a prompt.

6.3 The cleanup prompt

In the prompt editor: click the grey "Prompt name" text at the top (it is an empty text field, though it looks like a heading; the save button stays disabled until it is filled) and type Clean dictation. Switch Use System Template OFF. Paste this as the body:

You clean up dictated text. Return only the cleaned text, nothing else. Never answer, comment or add anything.

Rules:
- Remove filler words when they add no meaning: um, uh, so, basically, like, you know, I mean, sort of, kind of, right, well, actually.
- Fix punctuation, capitalisation and obvious grammar slips.
- Split run-on sentences into clear sentences.
- Otherwise keep the speaker's exact wording, tone and word order. Do not paraphrase.
- Never add information, greetings or sign-offs that were not spoken.
- If the text contains a question, clean it; do not answer it.
- If the text is already clean, return it unchanged.

Example
Input: So um basically I think we should uh move the meeting because like the report isn't ready you know
Output: I think we should move the meeting because the report isn't ready.

Click Save & Select in the prompt editor, then Save Changes on the mode. Both saves are required; closing the editor without the green Save Changes silently discards everything.

Use System Template must be off

With the toggle on, VoiceInk blends your rules into a generic template and the model stops removing fillers reliably (verified by testing the same model with and without it). Off means your prompt is in full control.

Test: dictate into TextEdit: "So um basically I think we should uh move the meeting to Thursday because like the report isn't ready yet you know". Expected output: "I think we should move the meeting to Thursday because the report isn't ready yet."

6.4 Auto-Learn Dictionary

VoiceInk can also use the model to learn recurring names and terms into your dictionary automatically. In its settings, point Auto-Learn Dictionary at the same Ollama model you use for enhancement; if it uses a different model, Ollama loads that model from cold for occasional calls, which is slow and can surface as an "auto-learning failed" message.

7. Modes and the personal dictionary

7.1 How modes switch automatically

Each mode bundles a transcription model, language, an AI prompt and Triggers. When you start dictating, VoiceInk checks the app in the foreground: if it matches a trigger, that mode's settings apply; otherwise your default mode is used. Each app can trigger only one mode. The recorder widget shows the active mode's name while you speak, so you can see the switch happen.

7.2 Two worked examples

Chat mode (messaging apps: light cleanup that keeps your casual tone). Create it via Modes → Add a new mode, name it Chat, add triggers for your chat apps (Claude, WhatsApp, Telegram, Slack), set Parakeet V3 and English, enable AI Enhancement with this prompt (system template off), named Chat cleanup:

You lightly clean up dictated chat messages. Return only the cleaned text, nothing else.

Rules:
- Remove filler words: um, uh, you know, I mean, sort of, kind of.
- Fix punctuation and obvious slips, but keep the casual tone exactly as spoken.
- Keep contractions, slang and informal phrasing. Do not formalise.
- Never add greetings, sign-offs or content that was not spoken.
- If the text contains a question, clean it; do not answer it.

The filler list is deliberately shorter here: in chat, words like "so" and "actually" carry tone, and stripping them makes messages read robotic.

Email mode (Mail, Outlook: full sentences, proper punctuation). Same procedure, prompt named Email cleanup:

You turn dictated text into clean email prose. Return only the cleaned text, nothing else.

Rules:
- Remove all filler words: um, uh, so, basically, like, you know, I mean, sort of, kind of, right, well, actually.
- Write complete, grammatical sentences with proper punctuation and capitalisation.
- Break the text into short paragraphs where the topic shifts.
- Keep the speaker's meaning and word choice; tighten only where dictation is clumsy.
- Never add information, greetings or sign-offs that were not spoken.
- If the text contains a question, clean it; do not answer it.
[Screenshot: Modes list showing Dictation, Chat and Email with their triggers]

7.3 Personal dictionary

Under Dictionary in the sidebar, add the words the transcriber is likely to miss: people's names, company and product names, technical terms, abbreviations. Two kinds of entry exist: vocabulary (words to recognise, for example "VoiceInk" or "Ollama") and word replacements (what you say → what gets typed). A real example from testing: "Claude" transcribed as "Cloud" until added to the dictionary. Add terms as you notice misses; the Auto-Learn feature (6.4) collects candidates for you over time.

8. Daily use

  • Hold, speak, release. Hold-to-talk is the reliable habit: the release is a natural "send", and the microphone is never left open. Use the tap-toggle only for long passages.
  • Speak naturally. Do not dictate punctuation ("comma", "full stop"); the model punctuates for you and spoken punctuation words harm the output.
  • Wait a beat after releasing. The text lands at the cursor a moment later (slightly longer with AI enhancement on). Typing immediately can interleave with the insertion.
  • Cancelling: press Esc while the recorder is up to abandon a recording.
  • When text does not paste: your words are not lost. Open History in VoiceInk and copy the transcription manually, then fix the Accessibility permission (section 9).
  • Watch the mode name on the recorder widget if output style surprises you; you may be in a different mode than you think.

9. Troubleshooting

Everything in the first group happened during the build this guide is based on.

SymptomCause and fix
error: cannot execute tool 'metal' due to missing Metal Toolchain, five CompileMetalFile failures in mlx-swift Xcode 26 and later ship without the Metal compiler, and each Xcode upgrade needs it again. Run xcodebuild -downloadComponent MetalToolchain, verify with xcrun metal --version, rebuild. (Section 3.2 avoids this by installing it up front.)
security: SecKeychainItemImport: MAC verification failed during PKCS12 import (wrong password?) The password is fine; the .p12 was made by OpenSSL 3 in its modern format, which macOS rejects. Re-export with -certpbe PBE-SHA1-3DES -keypbe PBE-SHA1-3DES -macalg sha1 (section 4.2 includes these flags).
Built app shows Signature=adhoc even though a signing identity was passed to the build Xcode 26 silently ignores non-Apple certificates and falls back to ad-hoc. Expected. Re-sign the finished app with codesign -f --deep --preserve-metadata=entitlements -s "VoiceInk Local" (section 4.3). The rebuild script does this automatically.
Prompt editor's Create & Select button stays disabled The "Prompt name" text at the top is an empty field, not a heading. Click it and type a name.
Mode or prompt edits vanish after closing the editor Two save layers: Save & Select inside the prompt editor, then the green Save Changes on the mode. Skipping the second discards everything, including newly created modes.
AI enhancement runs but ignores your rules (fillers survive) Switch Use System Template OFF in the prompt editor (section 6.3). If fillers still survive, the model is too small; use an 8B-class model.
"Auto-learning failed" message Usually a cold model load timing out. Point Auto-Learn at the same model as enhancement (section 6.4).
Accessibility permission lost after every rebuild You are on ad-hoc signing. Either re-grant it each time (System Settings → Privacy & Security → Accessibility) or create the certificate (section 4.2) and re-sign each build; then it survives. After switching from ad-hoc to the certificate, re-grant once.
Microphone not listed in VoiceInk Check macOS sees it: system_profiler SPAudioDataType. Reconnect USB, then revisit VoiceInk's Audio section. Check the Microphone permission is granted.
Model download stuck in AI Models Quit and relaunch VoiceInk and retry; check the connection. Parakeet lands in ~/Library/Application Support/FluidAudio/Models/; deleting a half-downloaded folder there forces a fresh download.
Ollama not reachable / enhancement fails Is Ollama running? curl http://localhost:11434 should answer "Ollama is running". Start the Ollama app, or ollama serve. Confirm the endpoint in the mode is http://localhost:11434 and the model name matches ollama list.
First dictation after setup is slow One-off CoreML model compilation. Subsequent runs are fast.
Dictation stopped working after an update; VoiceInk says accessibility permissions are not provided An update accepted inside the app replaced your build with the official one (section 10.1), and macOS no longer matches your permission to it. Run the update script in section 10.1, which rebuilds, reinstalls and removes the stray copies. Then clear the stale entry with tccutil reset Accessibility com.prakashjoshipax.VoiceInk, open VoiceInk, switch it on under System Settings → Privacy & Security → Accessibility, and quit and reopen VoiceInk. Settings, modes and history survive.

10. Updating and uninstalling

10.1 Updating

Never accept an update offered inside the app

Local builds still contain the developer's updater (Sparkle). If you accept an update from the Dashboard's update button or from Check for Updates…, it replaces your build with the official version. That version has a different signature, so macOS stops honouring your Accessibility and Microphone permissions, and dictation stops working with the message that accessibility permissions are not provided. This happened on the machine this guide is based on; the recovery steps are in section 9.

Update by rebuilding instead. Save the script below as ~/Developer/voiceink-build/rebuild.sh, make it executable once with chmod +x rebuild.sh, and run it whenever you want the latest version. As well as rebuilding, it reinstalls the Metal Toolchain if an Xcode upgrade removed it, turns the in-app update check off, removes the extra copies of the app the build leaves behind, and checks that Launch at login opens the copy in /Applications. Settings, modes, prompts and models all survive updates.

#!/bin/zsh
# Pull the latest VoiceInk source, rebuild, re-sign and reinstall.
# Also: reinstalls the Metal Toolchain after an Xcode upgrade, turns off
# the in-app update check (never accept those updates; see section 10.1),
# removes the extra copies of the app the build leaves behind, and checks
# that "Launch at login" opens the copy in /Applications.

set -euo pipefail

REPO="$HOME/Developer/voiceink-build/VoiceInk"
IDENTITY="VoiceInk Local"
BUNDLE_ID="com.prakashjoshipax.VoiceInk"
BUILT="$HOME/Downloads/VoiceInk.app"
DEST="/Applications/VoiceInk.app"
LSREGISTER="/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister"

quit_voiceink() {
  pgrep -x VoiceInk >/dev/null || return 0
  osascript -e "tell application id \"$BUNDLE_ID\" to quit" 2>/dev/null || true
  for i in {1..15}; do
    pgrep -x VoiceInk >/dev/null || return 0
    sleep 1
  done
  echo "ERROR: VoiceInk did not quit. Quit it manually and re-run." >&2
  exit 1
}

echo "==> Updating source..."
cd "$REPO"
git pull --ff-only
echo "    now at: $(git log -1 --format='%h %ci %s')"

echo "==> Checking Metal Toolchain (each Xcode major version needs its own)..."
if xcodebuild -showComponent MetalToolchain 2>&1 | grep -q 'Status: uninstalled'; then
  xcodebuild -downloadComponent MetalToolchain
fi

echo "==> Building (make local)..."
make local LOCAL_CODESIGN_IDENTITY=-

echo "==> Re-signing with '$IDENTITY'..."
if ! security find-identity -v -p codesigning | grep -q "$IDENTITY"; then
  echo "ERROR: signing identity '$IDENTITY' not found in keychain." >&2
  echo "Create it first: section 4.2 of the VoiceInk Build and Setup Guide." >&2
  exit 1
fi
codesign -f --deep --preserve-metadata=entitlements -s "$IDENTITY" "$BUILT"
codesign --verify --deep --strict "$BUILT"

echo "==> Installing to /Applications..."
quit_voiceink
defaults write "$BUNDLE_ID" VoiceInkChecksForUpdatesOnLaunch -bool false
rm -rf "$DEST"
ditto "$BUILT" "$DEST"
codesign --verify --deep --strict "$DEST"
echo "    version:   $(defaults read "$DEST/Contents/Info.plist" CFBundleShortVersionString)"
echo "    signature: $(codesign -dvv "$DEST" 2>&1 | grep '^Authority' | head -1)"

echo "==> Removing other copies..."
rm -rf "$BUILT" "$REPO/.local-build"
# Sparkle's download and install staging area (can hold an official build).
rm -rf "$HOME/Library/Caches/$BUNDLE_ID/org.sparkle-project.Sparkle"
# Xcode registers the build product with LaunchServices on every build.
# Unregister every VoiceInk path outside /Applications; `lsregister -u`
# only drops a record once its path no longer exists, hence after the rm.
"$LSREGISTER" -dump 2>/dev/null \
  | sed -n 's/^path: *\(.*VoiceInk.*\.app\) (0x[0-9a-f]*)$/\1/p' | sort -u \
  | while IFS= read -r p; do
      [[ "$p" == "$DEST"* ]] || "$LSREGISTER" -u "$p" 2>/dev/null || true
    done || true
"$LSREGISTER" -f "$DEST"

echo "==> Relaunching..."
open "$DEST"

echo "==> Checking login item..."
LOGIN_URL=$(sfltool dumpbtm 2>/dev/null | awk -v id="2.$BUNDLE_ID" \
  '$1=="Identifier:" && $2==id {f=1; next}
   f && $1=="URL:" && !done {print $2; done=1}') || true
if [[ "$LOGIN_URL" == "file://$DEST/" ]]; then
  echo "    OK: login item opens $DEST"
elif [[ -z "$LOGIN_URL" ]]; then
  echo "    NOTE: no login item. Turn on 'Launch at login' in VoiceInk settings if wanted."
else
  echo "    WARNING: login item opens $LOGIN_URL"
  echo "    Fix: in VoiceInk settings, turn 'Launch at login' off, then on again."
fi
echo "Done. VoiceInk updated, re-signed and running."

If you chose ad-hoc signing instead of the certificate, delete the re-signing block and expect to re-grant Accessibility after each update.

10.2 Uninstalling completely

  1. Quit VoiceInk, then delete /Applications/VoiceInk.app.
  2. App data and settings databases: ~/Library/Application Support/com.prakashjoshipax.VoiceInk/
  3. Transcription models: ~/Library/Application Support/FluidAudio/
  4. Preferences: defaults delete com.prakashjoshipax.VoiceInk
  5. Build materials: ~/Developer/voiceink-build/ and ~/VoiceInk-Dependencies/
  6. Permission entries: System Settings → Privacy & Security → Microphone and Accessibility; select VoiceInk and remove it with the − button.
  7. Optional: in Keychain Access, delete the "VoiceInk Local" certificate and its private key. Ollama and its models are separate; remove models with ollama rm <model> if wanted.
